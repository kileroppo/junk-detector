## Codebase Patterns
- CLI uses typer + Rich console. Test with typer.testing.CliRunner.
- All LLM calls go through src/core/scorer.score() - mock this for integration tests
- Config loads from config.yaml with YAML cache (src/core/config.py). reload_config() clears cache.
- MonitorService is the integration layer: Thunder (discovery) -> Queue -> Dispatcher (execution) -> Pipeline (scoring)
- Web extraction: _strip_noise -> _find_main_content -> _extract_text pipeline in src/extractors/web.py
- Tests in tests/ flat structure. conftest.py has shared fixtures (mock_llm_response, sample_junk_text, etc.)
- pytest-asyncio with asyncio_mode=auto - async tests just use async def
- API key validation pattern: check env var based on model name before calling scorer

- **Learnings for future iterations:**
  - typer.testing.CliRunner env parameter overrides os.environ for the CLI process - use it to test API key presence/absence
  - MonitorService._execute_task is the hook point for tracking individual scoring results
  - BeautifulSoup's NOISE_CLASSES pattern is the cheapest way to add extraction rules - just add class/id substrings
  - The scorer's cache check (content_hash in DB) can interfere with tests if not properly isolated - conftest.py resets dedup cache
  - Rich console output in tests needs to be checked via string matching on result.output (CliRunner captures it)
