# 鉴真规则引擎失败模式分析

## 概述

基于100条标注样本的规则引擎评估，系统准确率约为78%，其中主要失败模式集中在误报（False Positives）和漏检（False Negatives）两大类。本文档详细分析了各类失败原因并提出改进方向。

## 误报类型 (False Positives)

### 1. 规则过于宽泛

- **案例**: 正常技术文章包含"免费"导致误判
- **原因**: "免费"在正常语境下使用频率高，如"免费开源"、"免费试用"等合理场景
- **影响范围**: 约占所有误报的35%
- **典型样本**:
  - "这个项目完全免费开源，欢迎贡献代码" -> 被误判为scam
  - "限时免费课程：Python入门教学" -> 被误判为scam（实为正规教育平台）

### 2. 讽刺/反讽内容被误判

- **案例**: 吐槽文章使用夸张修辞被系统视为真实推销
- **原因**: 规则引擎无法理解语境和修辞手法，只能做字面匹配
- **影响范围**: 约占所有误报的15%
- **典型样本**:
  - "哈哈日入过万是不可能的，这种骗子话术大家别信" -> 被误判为scam
  - "震惊！我竟然写了一整天Bug" -> 被误判为emotional_manipulation

### 3. 引用/新闻报道被误判

- **案例**: 新闻文章引述诈骗话术进行科普
- **原因**: 系统无法区分"使用"和"引用"
- **影响范围**: 约占所有误报的20%
- **典型样本**:
  - 反诈宣传文章引用诈骗关键词进行警示教育
  - 学术论文讨论互联网营销话术

### 4. 正当商业内容被误判

- **案例**: 正规电商平台促销信息
- **原因**: 合法商业用语与垃圾推广使用相同关键词
- **影响范围**: 约占所有误报的30%
- **典型样本**:
  - 京东/天猫官方促销文案包含"优惠券"、"限时"
  - 正规品牌推荐使用"亲测有效"

## 漏检类型 (False Negatives)

### 1. 隐性软文逃逸

- **案例**: 精心伪装的商业软文通过评测形式呈现
- **原因**: 内容使用中性描述，关键词密度极低
- **影响范围**: 约占所有漏检的40%
- **典型样本**:
  - "最近换了XX品牌，感觉还不错" -> 隐性种草但关键词密度低
  - 以"个人体验分享"形式包装的付费推广

### 2. 新型诈骗话术未覆盖

- **案例**: 使用谐音字、拆字、或新造词规避关键词检测
- **原因**: 规则库需要持续更新，存在滞后性
- **影响范围**: 约占所有漏检的25%
- **典型样本**:
  - "曰入过W"（日入过万的变体）
  - "加V信"（加微信的变体）
  - 使用emoji或特殊字符分割关键词

### 3. 长文稀释效应

- **案例**: 大量正常内容中夹带少量推广
- **原因**: 当前基于整体关键词密度判断，长文中少量关键词密度被稀释
- **影响范围**: 约占所有漏检的20%
- **典型样本**:
  - 3000字技术文章最后一段植入推广链接
  - 正常分享中间插入一两句推广

### 4. 图文混合内容逃逸

- **案例**: 关键信息放在图片中，正文仅为引导语
- **原因**: 当前系统仅分析文字内容，无法处理图片
- **影响范围**: 约占所有漏检的15%
- **典型样本**:
  - 微信收款码图片 + "扫码加群"
  - 推广信息以长图形式发布

## 规则冲突与优先级问题

### combo规则相互抵消

- 当文章同时命中正面和负面信号时，最终得分可能不准确
- 例：高质量技术文章包含affiliate链接，信息密度高但同时有推广

### 阈值边界效应

- 得分在40-55区间的内容判定不稳定
- 微小变动（增删一个关键词）可能导致verdict跳变

## 改进方向

### 短期改进
1. **上下文窗口分析**: 在关键词前后检查否定词、引号等语境标记
2. **白名单机制**: 对已知正规媒体/平台降低灵敏度
3. **关键词分级**: 区分高置信度关键词（"日入过万"）和低置信度关键词（"免费"）

### 中期改进
1. **段落级评分**: 不仅整体评分，还对各段落独立评分
2. **来源权重**: 结合URL来源调整判定阈值
3. **用户反馈闭环**: 利用用户的"结果不对"反馈持续优化规则

### 长期改进
1. **LLM语义理解**: 对边界案例启用LLM进行语义分析
2. **多模态检测**: 引入图片OCR和视频字幕分析
3. **对抗样本训练**: 模拟攻击者策略，提前防御新型逃逸手法
